`Solidtype_heroui.Tooltip` is Kobalte's `Tooltip`, with the classes HeroUI's
own `tooltipVariants` gives and HeroUI's arrow. A `Button` inside it is its
trigger, as in HeroUI; anything else is wrapped in `Tooltip.Trigger`.

## Usage

<Example code={ExUsageCode} title="tooltip_usage.mlx"><ExUsage.make client:visible /></Example>

## Anatomy

```ocaml
<Tooltip>
  <Tooltip.Trigger><Button>"Hover for tooltip"</Button></Tooltip.Trigger>
  <Tooltip.Content>
    <Tooltip.Arrow />
    "Helpful information about this element"
  </Tooltip.Content>
</Tooltip>
```

### Global CSS

HeroUI's classes are global, so a stylesheet restyles every one, as with
HeroUI in React:

```css
@layer components {
  .tooltip {
    @apply rounded-xl shadow-lg;
  }

  .tooltip__trigger {
    @apply cursor-help;
  }
}
```

## Styling Reference

### Global Delay Configuration

A tooltip given no `delay_ms` or `close_delay_ms` reads the page's, as
HeroUI's does, else waits 1500 ms to open and 500 ms to close:

```css
:root {
  --tooltip-delay: 1500ms;
  --tooltip-close-delay: 500ms;
}
```

### CSS Classes

- `.tooltip`, `.tooltip__trigger`

### Interactive States

- **Entering**: `[data-entering="true"]`, while it appears
- **Exiting**: `[data-exiting="true"]`, while it disappears
- **Placement**: `[data-placement="top"]`, and the other sides

## How it is made

Kobalte's tooltip opens, closes, places itself and names its trigger's
description. As its pointer leaves the trigger, Kobalte keeps the tooltip
open while the pointer crosses toward it, where React Aria waits out its
close delay. The port keeps the tooltip on the page while HeroUI's exit
animation plays, and declares `data-entering` and `data-exiting` as React
Aria does, so HeroUI's keyframes run both ways.

Kobalte's arrow draws a shape of its own, so the port keeps it, hidden, where
Kobalte places it, and draws HeroUI's arrow there. `Tooltip.Trigger` is
Kobalte's trigger as the `<div role="button">` HeroUI's is, so a button
inside it is not a button inside a button.

## API Reference

Each prop beside the name HeroUI's React component gives it.

### Tooltip

| React | solidtype | Type | Default | Description |
|---|---|---|---|---|
| `delay` | `delay_ms` | `float` | `--tooltip-delay`, else 1500 | Before it opens |
| `closeDelay` | `close_delay_ms` | `float` | `--tooltip-close-delay`, else 500 | Before it closes |
| `trigger` | `trigger` | `` `hover `` \| `` `focus `` | `` `hover `` | What opens it |
| `isDisabled` | `is_disabled` | `bool` | `false` | Whether it never opens |
| `isOpen` | `is_open` | `bool` | | Whether it is open, controlled |
| `defaultOpen` | `default_open` | `bool` | `false` | Whether it starts open |
| `onOpenChange` | `on_open_change` | `bool -> unit` | | Told as it opens or closes |
| `children` | `children` | elements | | Its trigger and its content |

### Tooltip.Content

| React | solidtype | Type | Default | Description |
|---|---|---|---|---|
