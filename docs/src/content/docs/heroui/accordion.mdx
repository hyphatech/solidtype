`Solidtype_heroui.Accordion` is Kobalte's accordion with the classes HeroUI's
own `accordionVariants` gives: items, each a heading holding the button that
expands and collapses it, and the panel that follows. One item is expanded at
a time, or several, and any expanded item collapses again as HeroUI's does. A
[`Button`](/solidtype/heroui/button/) given `` slot=`trigger `` inside a heading is its
item's trigger, in HeroUI's look.

The up and down arrows move focus from one trigger to the next, round from the
last to the first, and Home and End to the first and the last, skipping a
disabled item, as Kobalte's accordion means to; Tab moves on as it does
elsewhere. Kobalte's own root never tells its list of triggers it has focus,
so the arrows would move nothing; each item tells it as focus comes in.

A panel stays on the page while collapsed, hidden until the browser's find in
page reaches a word in it, which expands its item; it grows and shrinks by
`--disclosure-panel-height`, as a [`Disclosure`](/solidtype/heroui/disclosure/)'s content
does.

classes to the icon itself, which a Solid component cannot do to an element

### Global CSS

HeroUI's classes are global, so a stylesheet restyles every accordion, as with
HeroUI in React:

```css
@layer components {
  .accordion {
    @apply rounded-xl bg-gray-50;
  }

  .accordion__trigger {
    @apply text-lg font-semibold;
  }
}
```

## Styling Reference

### CSS Classes

- `.accordion`, the root, and `.accordion--surface` on a surface
- `.accordion__item`, an item, its separator drawn after it
- `.accordion__heading`, the heading
- `.accordion__trigger`, its trigger
- `.accordion__indicator`, the chevron, or the span around an icon given
- `.accordion__panel`, the panel, and `.accordion__body` and
  `.accordion__body-inner` inside it

### Interactive States

- **Expanded**: `[aria-expanded="true"]` on the trigger, and
  `[data-expanded="true"]` on the item, the indicator and the panel
- **Hover**: `:hover` or `[data-hovered="true"]` on the trigger
- **Focus**: `:focus-visible` or `[data-focus-visible="true"]` on the trigger
- **Disabled**: `:disabled` or `[data-disabled="true"]` on the trigger, the
  item and the root
- **No separator**: `[data-hide-separator="true"]` on each item
- **Hidden**: `[aria-hidden="true"]` and `hidden="until-found"` on the panel
  while collapsed

## Beside React

Original HeroUI documentation: [Accordion](https://heroui.com/en/docs/react/components/accordion).

The same HeroUI Accordion twice, under the same props: in solidtype on the
left, in React on the right. Below them, every attribute of the two
accordions: a marked row is one they disagree on, and a dimmed row is a
framework's own, which no style reads. Each trigger's `aria-controls` names
its own panel by the id its framework made. Kobalte's panel is a region of the
page its trigger controls, where React Aria's is a group its trigger names;
both are accessible, and the port keeps Kobalte's.
