`Solidtype_heroui.Scroll_shadow` is a `<div>` that scrolls, with the classes
HeroUI's own `scrollShadowVariants` gives, faded at each edge it hides content
at. It measures itself as it scrolls, as it is resized and as its content
changes, as HeroUI's hook does, and declares each edge as that hook writes
it. Kobalte has no scroll shadow.

HeroUI's documentation: [ScrollShadow](https://heroui.com/en/docs/react/components/scroll-shadow).

### Global CSS

HeroUI's classes are global, so a stylesheet restyles every scroll shadow, as
with HeroUI in React:

```css
@layer components {
  .scroll-shadow {
    @apply rounded-xl border border-default-200;
  }

  .scroll-shadow--vertical {
    @apply pr-2;
  }
}
```

## Styling Reference

### CSS Classes

- `.scroll-shadow`, and `.scroll-shadow--vertical`,
  `.scroll-shadow--horizontal`, `.scroll-shadow--hide-scrollbar`

### CSS Variables

- `--scroll-shadow-size`, the fade's size, from `size`
- `--scroll-shadow-offset`, how far it scrolls before the fade starts, from
  `offset`
- `--scroll-shadow-scrollbar-size`, the gutter kept for a native scrollbar

### Data Attributes

- `[data-top-scroll]`, `[data-bottom-scroll]`, `[data-left-scroll]`,
  `[data-right-scroll]`: `"true"` where content is hidden at that edge,
  `"false"` where it is not
- `[data-top-bottom-scroll]`, `[data-left-right-scroll]`: content hidden at
  both edges
- `[data-orientation]`, `[data-scroll-shadow-size]`
- `[data-scroll-shadow-mode]`: `"auto"` where the fade follows the scroll,
  `"manual"` where `visibility` is given or it is disabled

A shadow is measured once it is in the browser, so a prerendered one marks no
edge until it is; where a browser has scroll-driven animations, HeroUI's
styles fade an `"auto"` shadow from its first paint without them.
