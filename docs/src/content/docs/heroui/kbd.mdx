`Solidtype_heroui.Kbd` is a `<kbd>` with the classes HeroUI's own
`kbdVariants` gives, each modifier drawn by its symbol and named by its
`<abbr>`'s title, as HeroUI's are. A key has no behaviour, so no Kobalte
component underlies it.

The same component in React: [HeroUI's Kbd](https://heroui.com/en/docs/react/components/kbd).

<Example code={UsageCode} title="kbd_usage.mlx"><Usage.make client:visible /></Example>

## Anatomy

```ocaml
<Kbd>
  <Kbd.Abbr key_value=`command />
  <Kbd.Content>"K"</Kbd.Content>
</Kbd>
```

## Customization

### Tailwind CSS

`class_` is added after HeroUI's classes, on the key and on each part.

<Example code={TailwindCode} title="kbd_tailwind.mlx"><Tailwind.make client:visible /></Example>

### Global CSS

HeroUI's classes are global, so a stylesheet restyles every key, as with
HeroUI in React:

```css
@layer components {
  .kbd {
    @apply bg-gray-100 dark:bg-gray-800 border-gray-300;
  }

  .kbd__abbr {
    @apply font-bold;
  }

  .kbd__content {
    @apply text-sm;
  }
}
```

## Styling Reference

### CSS Classes

## API Reference

Each prop beside the name HeroUI's React component gives it.

### Kbd

| React | solidtype | Type | Default | Description |
|---|---|---|---|---|
| `variant` | `variant` | `` [ `default \| `light ] `` | | Its look |
| `className` | `class_` | `string` | | Added after HeroUI's classes |
| `children` | `children` | elements | | Its symbols and text |

### Kbd.Abbr

| React | solidtype | Type | Description |
|---|---|---|---|
| `keyValue` | `key_value` | `Kbd.key` | The key whose symbol it draws |
| `className` | `class_` | `string` | Added after HeroUI's class |

### Kbd.Content

| React | solidtype | Type | Description |
|---|---|---|---|
| `className` | `class_` | `string` | Added after HeroUI's class |
| `children` | `children` | elements | The key's text |
