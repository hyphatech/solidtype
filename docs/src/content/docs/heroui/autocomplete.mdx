`Solidtype_heroui.Autocomplete` is a select whose popover holds a search
field that filters its list, on Kobalte's `Combobox`, with the classes
HeroUI's own `autocompleteVariants` gives. Its search is the `Search_field`
inside its `Autocomplete.Filter`, and its list the `List_box` beside it, as
in HeroUI; `Label`, `Description` and `Field_error` inside it name, describe
and qualify it.

## Usage

HeroUI's example draws the states chosen as tags, with a TagGroup, which is
not ported yet; here they are listed as the value draws them.

<Example code={ExUsageCode} title="autocomplete_usage.mlx"><ExUsage.make client:visible /></Example>

## Anatomy

```ocaml
<Autocomplete>
  <Label>...</Label>
  <Autocomplete.Trigger>
    <Autocomplete.Value />
    <Autocomplete.Clear_button />
    <Autocomplete.Indicator />
  </Autocomplete.Trigger>
  <Description>...</Description>
  <Autocomplete.Popover>
    <Autocomplete.Filter>
      <Search_field>
        <Search_field.Group>
          <Search_field.Search_icon />
          <Search_field.Input />
        </Search_field.Group>
      </Search_field>
      <List_box>
        <List_box.Item id="...">...</List_box.Item>
      </List_box>
    </Autocomplete.Filter>
  </Autocomplete.Popover>
</Autocomplete>
```

  }

    @apply rounded-xl;
  }

## How it is made

Kobalte's combo box filters its options by the search's text, whatever its
case or accents, or by the filter given, and keeps the focus in the search
while the arrows move through the list, as React Aria's autocomplete does.
Its list is the `List_box` beside the search, whose options join the
autocomplete while it is closed too, so its value shows the option chosen;
the search moves into the popover each time it opens, and starts empty.

A press on the trigger, or an arrow on its button, opens the list and gives
the search the focus; typing gives the first option the search keeps the
focus. Enter or a press chooses: in a choice of one the list closes and the
focus goes back to the button, where React Aria's is lost to the page. While
the list is open the page outside is hidden from a reader and no pointer
reaches it, as React Aria's modal popover does.

The search's input is Kobalte's combo box input, which tells a reader it
expands and which option it holds, where React Aria's is a search box that
controls the list.
