`Solidtype_heroui.Radio_group` is Kobalte's radio group in HeroUI's anatomy:
the group, each `Radio`, `Radio.Content`, the clickable label that holds
Kobalte's input, `Radio.Control` and `Radio.Indicator`. A `Label` in the group
names it and a `Description` describes it; a `Description` in a radio
describes that radio's input. Its state is declared as React Aria writes it:
Space chooses a radio and the arrow keys move the choice, and Enter presses a
radio's content as React Aria's does, though it chooses nothing.

## Customization

### Tailwind CSS

Each part's `class_` is added after HeroUI's classes, and HeroUI's state
attributes are Tailwind's `data-[...]` variants, as in React.

<Example code={RadioGroupTailwindCode} title="radio_group_tailwind.mlx"><RadioGroupTailwind.make client:visible /></Example>

### Global CSS

HeroUI's classes are global, so a stylesheet restyles every one, as with
HeroUI in React:

```css
@layer components {
  .radio-group {
    @apply gap-2;
  }

  .radio__control {
    @apply border-2 border-accent;
  }
}
```

## Styling Reference

### CSS Classes

- `.radio-group`, with `.radio-group--primary` and `.radio-group--secondary`
- `.radio`, `.radio__content`, `.radio__control`, `.radio__indicator`

A disabled radio is styled by `[data-disabled="true"]` on `.radio`: there is
no `.radio--disabled`.

### Interactive States

- **Selected**: `[data-selected="true"]` or `[aria-checked="true"]`
- **Hover**: `:hover` or `[data-hovered="true"]`
- **Focus**: `:focus-visible` or `[data-focus-visible="true"]`
- **Pressed**: `:active` or `[data-pressed="true"]`
- **Disabled**: `:disabled` or `[data-disabled="true"]`
- **Invalid**: `[data-invalid="true"]` or `[aria-invalid="true"]`
