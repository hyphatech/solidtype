`Solidtype_heroui.Label` is HeroUI's label, with the classes HeroUI's own
`labelVariants` gives. Inside a switch's or a checkbox's content it is a
`<span>`, since the content is the clickable label already; anywhere else it is
a `<label>`. The [Switch](../switch/) and [Checkbox](../checkbox/) pages show
it in its fields.

### Not yet

HeroUI's Required, Disabled and Invalid labels: the port does not take
`isRequired`, `isDisabled` or `isInvalid` yet, though HeroUI's styles have
their classes.

## Customization

### Global CSS

HeroUI's classes are global, so a stylesheet restyles every one, as with
HeroUI in React:

```css
@layer components {
  .label {
    @apply font-semibold;
  }
}
```

## Styling Reference

### CSS Classes

- `.label`
- States: `.label--required`, `.label--disabled`, `.label--invalid`

## API Reference

Each prop beside the name HeroUI's React component gives it.

### Label

| React | solidtype | Type | Description |
|---|---|---|---|
| `className` | `class_` | `string` | Added after HeroUI's classes |
| `children` | `children` | elements | Its text |
| `isRequired`, `isDisabled`, `isInvalid` | — | | Not yet |

### Label.Slot

How a label renders below a part, given its classes and its children, as
React Aria's `LabelContext` gives it: `Switch.Content` and `Checkbox.Content`
make it a `<span>`, since a label in a label is not HTML.
