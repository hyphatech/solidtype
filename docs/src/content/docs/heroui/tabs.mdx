`Solidtype_heroui.Tabs` is Kobalte's tabs with the classes HeroUI's own
`tabsVariants` gives: a list of tabs, and a panel for each, shown while its
tab, of the same `id`, is selected. The arrows of its orientation move
between the tabs, round from the last to the first, and Home and End to
either end, skipping a disabled tab; focus selects the tab it reaches, or
Enter and Space do with `` keyboard_activation=`manual ``.

The selected tab's indicator slides from the tab selected before, as HeroUI's
styles animate it. A tab and its panel are named by their `id`, which each
takes; HeroUI's take one too, without which a panel has no tab.

```ocaml
      </Tabs.Tab>
    </Tabs.List>
  </Tabs.List_container>
  <Tabs.Panel id="..." />
</Tabs>
```

### Links

A tab given an `href` is a link, an `<a>`: a press or Enter follows it, as
any link is followed, and never selects it, so the tab selected is the one
`selected_key` names, the route an application's router says is open. Its
arrows still move focus along the tabs. A disabled tab has no `href`, so it
is never followed. HeroUI's Render Function example makes its tabs links
through Next's `Link`; here each is a link to a hash, which the example's
selection follows.

<Example code={LinksCode} title="tabs_links.mlx"><Links.make client:visible /></Example>

React Aria calls `onSelectionChange` with the tab still selected each time a
link tab is pressed, and selects a link tab that End or Home reaches once a
link has been followed by Enter; the port tells nothing and selects nothing,
whichever key or press reaches a link.

### Global CSS

HeroUI's classes are global, so a stylesheet restyles every tabs, as with
HeroUI in React:

```css
@layer components {
  .tabs__list {
    @apply rounded-xl border border-border bg-surface p-1;
  }

  .tabs__indicator {
    @apply rounded-lg bg-foreground shadow-sm;
  }
}
```

## Styling Reference

### CSS Classes

- `.tabs`, the root, and `.tabs--secondary`, `.tabs--align-start` and
  `.tabs--align-end`
- `.tabs__list-container`, and inside it `.tabs__list-container__scroller`,
  `.tabs__list-container__scroll-prev` and `.tabs__list-container__scroll-next`
- `.tabs__list`, `.tabs__tab`, `.tabs__indicator`, `.tabs__separator`
- `.tabs__panel`

### Interactive States

- **Selected**: `[aria-selected="true"]` and `[data-selected="true"]` on the
  tab
- **Hover**: `:hover` or `[data-hovered="true"]` on the tab
- **Focus**: `:focus-visible` or `[data-focus-visible="true"]` on the tab
- **Disabled**: `[aria-disabled="true"]` and `[data-disabled="true"]` on the
  tab
- **Orientation**: `[data-orientation]` on the root, the list and the panel

## Beside React

Original HeroUI documentation: [Tabs](https://heroui.com/en/docs/react/components/tabs).

The same HeroUI Tabs twice, under the same props: in solidtype on the left, in
React on the right. Below them, every attribute of the two roots: a marked
row is one they disagree on, and a dimmed row is a framework's own, which no
style reads.

A tab is Kobalte's button where React Aria's is a div, each of role `tab`.
A panel names no orientation, as React Aria's names none, so the spacing
HeroUI's styles would give it by its orientation reaches neither, and a panel
sits as close to its list as on heroui.com. React Aria marks its root focused while a tab is,
which no style reads and the port does not.
