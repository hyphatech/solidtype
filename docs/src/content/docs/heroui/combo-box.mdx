`Solidtype_heroui.Combo_box` is Kobalte's `Combobox`, with the classes
HeroUI's own `comboBoxVariants` gives. Its input is the `Input` inside its
input group, and its list the `List_box` inside its popover, as in HeroUI;
`Label`, `Description` and `Field_error` inside it name, describe and
qualify it.

```ocaml
<Combo_box>

    <List_box>

    </List_box>
  </Combo_box.Popover>
```

## How it is made

Kobalte's combo box filters its options by the input's text, whatever its
case or accents, keeps the focus in its input while the arrows move through
the list, chooses by Enter or a press, and closes on Escape, as React Aria's
does. Its list is the `List_box` inside its popover, which a combo box takes
as its own: the list's options join the combo box while it is closed too, so
its input can show the option chosen, and are drawn while Kobalte's filter
keeps them.

Focus opens the list with every option, and so does the trigger; typing
filters it. Escape on a closed list puts back the text of the option chosen,
and leaving the input does too, unless custom values are allowed. A form is
sent the ids chosen by hidden inputs, or the input's text where it is the
value, as React Aria sends them.

While the list is open, the page outside stays as a reader found it, as
Kobalte's combo box leaves it; React Aria's hides it. Kobalte hides it only
while its combo box is modal, which would also hold the page's pointer and
scroll.
