`Solidtype_heroui.Fieldset` is a `<fieldset>` with the classes HeroUI's own
`fieldsetVariants` gives, its legend, the group of its fields and its actions.
Kobalte has no fieldset. While it is `disabled`, it gives the buttons, links
and radio groups inside it the state, as HeroUI's gives React Aria's: the
browser disables a native button or input inside a disabled fieldset, but
neither a group nor the state HeroUI's styles read.

## Anatomy

```ocaml
<Fieldset>
  <Fieldset.Legend>"Profile"</Fieldset.Legend>
  <Fieldset.Group>(* its fields *)</Fieldset.Group>
  <Fieldset.Actions>(* its buttons *)</Fieldset.Actions>
</Fieldset>
```

## Customization

### Global CSS

HeroUI's classes are global, so a stylesheet restyles every fieldset, as with
HeroUI in React:

```css
@layer components {
  .fieldset {
    @apply gap-6 rounded-lg border p-6;
  }

  .fieldset__legend {
    @apply text-2xl font-bold;
  }
}
```

## Styling Reference

### CSS Classes

- `.fieldset`, `.fieldset__legend`, `.fieldset__field-group`,
  `.fieldset__actions`

### Interactive States

- **Disabled**: `[data-disabled="true"]`, from which HeroUI's styles show
  the fields inside disabled

## API Reference

Each prop beside the name HeroUI's React component gives it.

### Fieldset

| React | solidtype | Type | Default | Description |
|---|---|---|---|---|
| `disabled` | `disabled` | `bool` | `false` | Whether it and what is inside it are disabled |
| `name` | `name` | `string` | | Its name in a form |
| `className` | `class_` | `string` | | Added after HeroUI's classes |
| `children` | `children` | elements | | Its legend, groups and actions |

### Fieldset.Legend, Fieldset.Group, Fieldset.Actions

| React | solidtype | Type | Description |
|---|---|---|---|
| `className` | `class_` | `string` | Added after HeroUI's class |
| `children` | `children` | elements | Its content |
