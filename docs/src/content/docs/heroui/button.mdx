`Solidtype_heroui.Button` is Kobalte's `Button.Root`, a native `<button>`, with
the classes HeroUI's own `buttonVariants` gives and the state its styles read,
declared as React Aria writes it.

HeroUI's documentation: [Button](https://heroui.com/en/docs/react/components/button).

### Global CSS

HeroUI's classes are global, so a stylesheet restyles every button, as with
HeroUI in React:

```css
@layer components {
  .button {
    @apply font-semibold uppercase;
  }

  .button--primary {
    @apply bg-indigo-600 hover:bg-indigo-700;
  }
}
```

## Styling Reference

### CSS Classes

The classes HeroUI's button styles define, which `variant`, `size`,
`full_width` and `is_icon_only` choose:

- `.button`, and its sizes `.button--sm`, `.button--md`, `.button--lg`
- `.button--primary`, `.button--secondary`, `.button--tertiary`,
  `.button--outline`, `.button--ghost`, `.button--danger`,
  `.button--danger-soft`
- `.button--icon-only`, `.button--full-width`

### Interactive States

HeroUI's styles read a pseudo-class or a data attribute for each; the port
declares each attribute as React Aria writes it:

- **Hover**: `:hover` or `[data-hovered="true"]`
- **Pressed**: `:active` or `[data-pressed="true"]`
- **Focus**: `:focus-visible` or `[data-focus-visible="true"]`
- **Disabled**: `:disabled` or `[data-disabled="true"]`

Kobalte writes only `data-disabled`, and empty, so the port keeps the rest
itself, by `Solidtype_heroui.Interaction`, as React Aria does: hovered by a
mouse but never a touch, pressed by a pointer or by Enter and Space,
focus-visible only after a key. Its test puts the port and the same Button in
React through the same steps and compares what each shows after every one.

string React takes, a hyphen written as an underscore: `` `danger_soft `` is
