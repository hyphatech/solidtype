`Solidtype_heroui.Button` is Kobalte's `Button.Root`, a native `<button>`, with
the classes HeroUI's own `buttonVariants` gives. Its look is HeroUI's props;
its behaviour is Kobalte's.

## Beside React

The same HeroUI Button twice, under the same props: in solidtype on the left,
in React on the right. Below them, every attribute of the two elements: a
marked row is one they disagree on, and a dimmed row is a framework's own --
Solid's hydration key, React Aria's markers and the id it generates -- which
no style reads. Hover, focus and press the buttons to see the state each
sets.

## State

HeroUI's styles read the state React Aria writes on an element:
`data-hovered`, `data-pressed`, `data-focused`, `data-focus-visible` and
`data-disabled`, each `"true"` or absent. Kobalte writes only `data-disabled`,
and empty, so the port keeps them itself, by
`Solidtype_heroui.Interaction`, as React Aria does: hovered by a mouse but
never a touch, pressed by a pointer or by Enter and Space, focus-visible only
after a key. Its test puts the port and the same Button in React through the
same steps and compares what each shows after every one.
