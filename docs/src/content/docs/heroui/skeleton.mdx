`Solidtype_heroui.Skeleton` is a `<div>` with the classes HeroUI's own
`skeletonVariants` gives, shaped by its `class_`. Kobalte's Skeleton is a
wrapper that hides its content while it loads, with a role and sizes of its
own; HeroUI's is the placeholder alone, which this is, with no behaviour.

## Customization

### Tailwind CSS

`class_` is added after HeroUI's classes.

<Example code={TailwindCode} title="skeleton_tailwind.mlx"><Tailwind.make client:visible /></Example>

### Global CSS

HeroUI's classes are global, so a stylesheet restyles every skeleton, as with
HeroUI in React:

```css
@layer components {
  .skeleton {
    @apply bg-surface-secondary/50;
  }

  .skeleton--pulse {
    @apply animate-pulse opacity-75;
  }

  .skeleton--none {
    @apply opacity-50;
  }
}
```

### Global Animation Configuration

The page's `--skeleton-animation` is the animation of every skeleton given
none, `shimmer`, `pulse` or `none`, as in React:

```css
:root {
  --skeleton-animation: pulse;
}

.dark, [data-theme="dark"] {
  --skeleton-animation: shimmer;
}
```

A skeleton reads it once it is in the browser, never on the server, so a
prerendered skeleton hydrates as it was rendered, a shimmer, and then takes
the page's. A value it does not know is a shimmer.
