`Solidtype_heroui.List_box` is Kobalte's `Listbox`, with the classes HeroUI's
own `listboxVariants`, `listboxItemVariants` and `listboxSectionVariants`
give. HeroUI's `Label`, `Description`, `Header` and `Separator` go inside its
options and sections, as in React.

## Anatomy

```ocaml
<List_box aria_label="...">
  <List_box.Item id="...">
    <Label>...</Label>
    <Description>...</Description>
    <List_box.Item_indicator />
  </List_box.Item>
  <Separator />
  <List_box.Section>
    <Header>...</Header>
    <List_box.Item id="..." />
  </List_box.Section>
</List_box>
```

options in view. The port draws every option, here a thousand: Kobalte's
list is told it is virtualized only so that the port may draw it.

### Global CSS

HeroUI's classes are global, so a stylesheet restyles every one, as with
HeroUI in React:

```css
@layer components {
  .list-box {
    @apply rounded-lg border border-border bg-surface p-2;
  }

  .list-box-item {
    @apply rounded px-2 py-1 cursor-pointer;
  }

  .list-box-item--danger {
    @apply text-danger;
  }
}
```

## Styling Reference

### CSS Classes

- `.list-box`, `.list-box--default`, `.list-box--danger`
- `.list-box-item`, `.list-box-item--default`, `.list-box-item--danger`,
  `.list-box-item__indicator`, and the indicator's
  `[data-slot="list-box-item-indicator--checkmark"]`
- `.list-box-section`, and `.header` for its title
- `[data-slot="separator"]` within the list

### Interactive States

- **Hover**: `[data-hovered="true"]` on an option
- **Focus**: `:focus-visible` or `[data-focus-visible="true"]`, and
  `[data-focused="true"]` on the option with the focus
- **Pressed**: `[data-pressed="true"]` on an option
- **Selected**: `[data-selected="true"]` and `[aria-selected="true"]` on an
  option
- **Disabled**: `[data-disabled="true"]` on an option
- **Selection**: `[data-selection-mode="single"]` or `"multiple"` on the
  options

## How it is made

Kobalte's list moves the focus between its options by the arrows and by
what is typed, and selects one or many, as React Aria's does. Kobalte's list
is made from its options as data, where HeroUI's is written as elements: so
each option, section and separator joins the list as it is made, in its
order, and the list hands Kobalte its options alone and draws them in its
sections, between its separators, as React Aria's does. A section is a
`<section>` with the role `group`, named by its header.

Kobalte counts each option's place for a reader with `aria-posinset` and
`aria-setsize`, which React Aria leaves to its list.
