`Solidtype_heroui.Select` is Kobalte's `Select`, with the classes HeroUI's
own `selectVariants` gives. Its list is a `List_box` inside its popover, as
in HeroUI; `Label`, `Description` and `Field_error` inside it name, describe
and qualify it.

<Example code={ExUsageCode} title="select_usage.mlx"><ExUsage.make client:visible /></Example>

## Anatomy

```ocaml
<Select>
  <Label>...</Label>
  <Select.Trigger>
    <Select.Value />
    <Select.Clear_button />
    <Select.Indicator />
  </Select.Trigger>
  <Description>...</Description>
  <Select.Popover>
    <List_box>
      <List_box.Item id="...">...</List_box.Item>
    </List_box>
  </Select.Popover>
</Select>
```

## How it is made

Kobalte's select opens its list from its trigger, moves the focus through it
by the arrows and by what is typed, chooses one option or many, and closes
on Escape or a press outside, giving the focus back to its trigger, as React
Aria's does. Its list is the `List_box` inside its popover, which a select
takes as its own: the list's options join the select while it is closed
too, so its value can draw the option chosen as the list draws it, and are
Kobalte's select's options. While it is open the page outside is hidden from
a reader, as React Aria's modal popover hides it.

A clear button is a `<span>` inside the trigger, since a button in a button
is not HTML, so Backspace or Delete on the trigger clears too, as HeroUI's
does.
