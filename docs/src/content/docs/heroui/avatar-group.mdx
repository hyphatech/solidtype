`Solidtype_heroui.Avatar_group` is a `<div>` of `Solidtype_heroui.Avatar`s,
with the classes HeroUI's own `avatarGroupVariants` gives. It gives the
avatars inside it its `size`, `color` and `variant`, each where an avatar sets
none itself, shows the first `max` of them, and counts the rest. Kobalte has
no group.

## Anatomy

```ocaml
<Avatar_group>
  <Avatar>
    <Avatar.Image alt="Ada Lovelace" src="/ada.png" />
    <Avatar.Fallback>"AL"</Avatar.Fallback>
  </Avatar>
  <Avatar_group.Count>"+3"</Avatar_group.Count>
</Avatar_group>
```

## Counting

React counts a group's own children. Solid cannot single them out, so an
avatar joins its group as it is made, and is counted in the order the
avatars were made: an avatar a `For` adds later is counted after the others,
wherever it is shown.

## Customization

### Tailwind CSS

`class_` is added after HeroUI's classes; a group that means something, as
assignees do, takes a role and a name.

<Example code={TailwindCode} title="avatar_group_tailwind.mlx"><Tailwind.make client:visible /></Example>

### Global CSS

HeroUI's classes are global, so a stylesheet restyles every group, as with
HeroUI in React. The overlap is `--avatar-group-overlap`, `0.5rem` by
default, and the seam `--avatar-group-seam`.

## Styling Reference

### CSS Classes
