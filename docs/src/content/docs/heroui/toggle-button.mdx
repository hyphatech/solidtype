`Solidtype_heroui.Toggle_button` is Kobalte's toggle button with the classes
HeroUI's own `toggleButtonVariants` gives, and the state HeroUI's styles read:
`data-selected` while it is on, and the hover, press and focus React Aria
shows. Inside a [`Toggle_button_group`](../toggle-button-group/) it is the
group's button of its `id`.

### Global CSS

HeroUI's classes are global, so a stylesheet restyles every toggle button, as
with HeroUI in React:

```css
@layer components {
  .toggle-button {
    @apply bg-purple-500 text-white;
  }

  .toggle-button--icon-only {
    @apply rounded-lg;
  }
}
```

## Styling Reference

### CSS Classes

- `.toggle-button`, and its sizes `.toggle-button--sm`, `.toggle-button--md`,
  `.toggle-button--lg`
- `.toggle-button--default`, `.toggle-button--ghost`
- `.toggle-button--icon-only`

### Interactive States

- **Selected**: `[data-selected="true"]`
- **Hover**: `:hover` or `[data-hovered="true"]`
- **Pressed**: `:active` or `[data-pressed="true"]`
- **Focus**: `:focus-visible` or `[data-focus-visible="true"]`
- **Disabled**: `:disabled` or `[data-disabled="true"]`

## Beside React

HeroUI documents the same component in React: [ToggleButton](https://heroui.com/en/docs/react/components/toggle-button).

The same HeroUI ToggleButton twice, under the same props: in solidtype on the
left, in React on the right. Below them, every attribute of the two buttons:
a marked row is one they disagree on, and a dimmed row is a framework's own,
which no style reads. React Aria writes `tabindex="0"` on the button, which a
button has anyway; Kobalte marks a button that is on with an empty
`data-pressed`, which HeroUI's styles, reading `data-pressed="true"` for a
press, never match.
